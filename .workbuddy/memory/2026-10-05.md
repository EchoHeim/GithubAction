### 三个实测踩到的坑（都写进代码注释了，别改回去）

1. **登录入口在首页，不在 `/login`。**
   `https://www.ns211.com/login` 的 title 是「找回密码 - NS中文网」，页面上既没有登录按钮也没有登录弹窗。
   入口是首页导航栏的 `<div class="login-btn navbar-button">` —— **div 不是 `<a>`**。

2. **登录表单在 SweetAlert2 里，`#popup-signup` 永远 `display:none`。**
   `open_signup_popup()` 把 `#popup-signup` 的 HTML 搬进 `Swal.fire({html: ...})`。
   所以「等 `#popup-signup` 可见」永远等不到，必须判`.swal2-container` 里有 `input[name=username]`。

3. **`.login-btn` 的点击绑定要等 jQuery ready 才挂上。**
   base.py 用了 `page_load_strategy="none"`，导航一返回 DOM 可能还没绑好，点一下毫无反应。
   解法：**反复点直到表单出现**，而不是点一次就干等。

### 签到按钮的选择器陷阱（首跑失败后取证修正）

首版以为页面上 `click-qiandao` 有两处（悬浮条 + 侧栏），选「侧栏优先」即可。**错了**，CI 首跑直接
`未找到签到按钮`。取证结论（curl 静态 HTML + 主题 CSS/JS）：

1. **侧栏用户卡片里的按钮类名是 `btn-qiandao`，不是 `click-qiandao`。**
   app.css 里有 `.widget-userinfo .btn-qiandao`（圆角胶囊 + `#f2f7ff` 底色 + `.75rem` 字号），
   与用户截图里侧栏那个蓝色「签到」按钮一致。
2. **全站唯一绑点击事件的是 `$(".click-qiandao")`（app.js 全文仅此一处），
   而它所在的 `.rollbar` 悬浮条在 app.css 里是 `display: none`** —— 不可见也不可点，
   `find_visible()` 的 `is_displayed()` 必然落空。首版选择器全部指向这个不可见元素。
3. `btn-qiandao` 在 app.js 里出现 **0 次**，子主题 `xy-tags.js` 里也没有，
   所以它是否同时挂了 `click-qiandao` 类**无法在未登录状态下确认**。

**最终解法（不赌类名）**：先按UI 点按钮，12s 内拿不到回执就**直接调接口**兜底。
接口契约已用 curl + 真浏览器双向验证：

    POST https://www.ns211.com/wp-admin/admin-ajax.php
    body: action=user_qiandao
    → {"status":"0","msg":"\u8bf7\u767b\u5f55\u540e\u7b7e\u5230"}   # 未登录时

- **status 是字符串 `"0"` / `"1"`，不是 int** —— 判定要用 `int(status) == 1`。
- msg 是 JSON unicode 转义，`json.loads` 会自动解成中文。
- 在页面里用 `caozhuti.ajaxurl` + **同步 XHR**（`xhr.open('POST', url, false)`）
  可以在 `execute_script` 里直接拿到返回体，不依赖 SweetAlert2 弹窗。

### 附带修掉的 bug：积分读数假数

`read_points` 原用全页 `//*[contains(text(),'积分')]`，会抓到正文签到规则说明里的

### 验证方式

- 假凭据真浏览器：登录入口命中 → 弹窗打开 → 表单填入 → 提交 → 站点返回
  「用户名或密码错误」→ 正确判失败并留现场。
- 签到接口：curl 与真浏览器同步 XHR 双向验证，`status`/`msg` 解析路径确认可用。
- 登录态下的签到 UI 点击仍未本地验证（需真凭据），但已加接口兜底，
  最差情况也会拿到站点权威回执而不是「找不到按钮」。

## 掘金沸点文案池化（不再每天发同一句）

`Selenium/Check-in/juejin.py`：原来 `PINS_TEXT` 默认硬编码「今天也要好好写代码呀~」，
每天两轮都发同一句（第二轮只加「（2）」后缀），像刷屏且易被当重复内容。

改法：
- 新增常量 `PINS_TEXT_POOL`（20 条程序员日常吐槽向短句）。
- 新增 `pick_pin_texts(rounds)`：在 `pins_activity` 的轮次循环**外**一次性抽好 N 轮文案，
  `random.shuffle` 后取前 N 条 → 同一次运行内**绝不重样**；轮数超池容量才退回「随机+轮次后缀」。
- `JUEJIN_PINS_TEXT` 语义变了：默认空 = 走随机池；显式设置 = 固定发那一条（手动兜底口子保留）。
- `_round_text()` 保留，但只在固定文案模式 / 超容量兜底时才走。
- 回归测试：T20 保留（固定模式后缀），新增 T20b（池=20 条不重复、抽 2 轮不同、12 次至少出现 5 种）；
  T22 改为断言「两轮内容不同且不带（2）后缀」。T20b/T22 都需在跑前把 `m.PINS_TEXT` 置空。
