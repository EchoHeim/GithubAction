## CleanWorkflows.py 本机跑通改造（10:05）

lodge 让「本地运行一下 CleanWorkflows.py」。原版（2024-08）在本机**一步都跑不动**，
逐条实测定位到三处失效点（都不是「选择器写错」，是环境和页面变了）：

1. **代理变量**：本 shell 带 `http_proxy=http://127.0.0.1:7315`（WorkBuddy 出口代理），
   Selenium 的 urllib3 把它套到发往 localhost:chromedriver 的请求上 →
   会话建得起来但任何命令都回 `WebDriverException: unhandled request`。
   和 `Check-in/run_local.py` 里处理的是同一个坑，原来 CleanWorkflows 没做这层处理。
2. **GitHub 登录页**：`#password` 初始 displayed+enabled 都正常，**只要往 `#login_field`
   输入内容，前端 JS 立刻把密码框置 disabled，15s 内不恢复**（挂 `navigator.webdriver`
   掩码也拦不住，不是自动化指纹触发的）。对密码框 `send_keys` 必抛
   `ElementNotInteractableException`。解法：JS 置 `disabled=false` + 赋值 + 派发
   input/change；已用 performance 日志验证 `/session` 的 POST body 里确实带上了
   `login=…&password=…`。顺带：`//*[@value="Sign in"]` 已失效 → 用 `input[name="commit"]`。
3. **删除流程的绝对 XPath**：老路径依赖 `split-page-layout` 容器，现在该容器整页 0 命中。
   行容器实际是 `Box-row js-socket-channel js-updatable-content`；行内菜单仍是
   `<details><summary aria-haspopup="menu">` + `<ul class="dropdown-menu">`，
   但**匿名态只渲染 `View workflow file`，`Delete run` 只在登录态存在** →
   必须按文本匹配，不能按 `li[2]` 序号。`//*[@id="actions-tab"]` 和
   `//*[@class="next_page"]` 反而**仍然有效**（新旧选择器可以共存，逐个验，别整体重写）。

## 补：加了 REST API 版 CleanWorkflowsApi.py（10:15）

lodge 问「REST API 这个怎么用」，直接给了可跑的脚本。

**接口就三条**：`GET /repos/{o}/{r}`（探活）、
`GET /repos/{o}/{r}/actions/runs?per_page=100&page=N`（列表，**公开仓库免 token**）、
`DELETE /repos/{o}/{r}/actions/runs/{id}`（删除，**必须 token**，成功 204 无响应体）。
token 要 **Actions: Read and write**（细粒度 PAT），经典 PAT 勾 `workflow`。
GitHub MCP 连接器**没有** actions 能力（可用工具里只有 issues/PR/code/repo 那批），别指望它。

**关键实测发现：代理方向和 Selenium 那版是反的。**
- 直连 `api.github.com`：TCP 通，但 **`403 rate limit exceeded`** —— 本机出口 IP 的
  匿名额度已耗尽（60/小时，共享 IP 很容易撞上）。
- 走环境代理（本 shell 的 `HTTPS_PROXY`）：**200 OK**。
所以 API 版**不动环境变量**（requests 默认 trust_env），Selenium 版**必须清空**。
同一台机器上两条路对代理的要求相反，这个坑值得记。

**验证到哪一步**：`--dry-run` 完整跑通 —— 868 条记录、分 9 页拉全、
保留最新 100 条后候选 768 条（时间范围 2025-11-17 → 2026-09-18）。
无 token 跑 `--delete` 快失败提示；假 token 报 `401 Bad credentials（token 无效或过期）`。
真删那步没验（手上没 token），但 DELETE 的 URL 形状是官方文档标准形态。

设计取舍：`--keep`（默认 100）、`--max`、`--workers`（默认 8 并发）、
默认预演必须显式 `--delete`、**权限失败立刻中止剩余请求**（403/401 是确定性的，
没必要把另外 700 个请求白打完）、429/5xx 指数退避、404 当成功（已经不在了）。

## 52pojie 回帖失败「抱歉，您」：不是站点拒了，是自己把话截断了（10:15）

lodge 贴 CI 日志：签到正常（今日已签到、56 积分），回帖那步抛
`RuntimeError: 回帖被拒（抱歉，您）`，dump 出的 `reply_rejected_015507.html` 也看不出原因。

### 定位过程（两步，第一步零副作用）

1. **提交前基线探针**（临时脚本，已删）：注入 Cookie 打开目标帖，**不填框不点击**，
   把 `read_reply_result` 扫的那份 blob 分段打出来 —— 所有 script、`#fastpostreturn`、
   `#messagetext`、body 可见文本**全部干净**（ret len=0，归类 none）。
   → **排除「页面固有文本误报」**，"抱歉，您" 是提交后服务端真回来的。
2. **本地端到端复现失败**：随后本机访问该帖页连续 5 次导航都不提交
   （`[WARN] 导航后 25s 内没有新文档提交`，URL 卡在首页；首页照常、登录态 True）。
   也就是说**本地拿不到 CI 那份现场**，只能靠改代码让下次日志自证。

### 根因：判定表的泛短语把原因吃了（代码缺陷，不是站点问题）

```python
for marker in REPLY_ERROR_MARKERS:   # ❌ 顺序命中即返回
    if marker in blob:
        return "error", marker       # 「抱歉，您」排第一 → 只回 3 个字
```

服务端真实文案多半是「抱歉，您两次发表间隔少于 15 秒」/「帖子小于 10 个字符的限制」/
「填写的内容包含不良信息」——**三种原因的处理方式完全不同**，只报「抱歉，您」等于没报。

### 改了什么（`ChromeSelenium/Check-in/52pojie.py`，+143 行）

- 拆出 `collect_reply_blob()`（只采集）+ `classify_reply_blob(blob, baseline)`（**纯函数**判定）
  + `_reply_snippet()`（取整句）；`read_reply_result(driver, baseline="")` 只做采集+转发。
- 判定三条新规：**取最长命中**（泛短语只兜底）、**带整句进日志与异常**、
  **与提交前基线做差分**（`count(m) > count_baseline(m)` 才算数，页面固有文本不算）。
- `pending` 独立归类：`需要审核`/`待审核` 从错误表挪出 —— 那其实是**已经发出去了**。
- `REPLY_ERROR_MARKERS` 补 12 条无歧义文案（帖子小于 / 不良信息 / 绑定手机 /
  所在的用户组 / 已被关闭 / 重复回复 …）。
- `REPLY_TEXT` 默认加长为「谢谢分享，正好需要这个工具，感谢楼主~」：
  Discuz 有最小字数限制，旧的「谢谢分享~」只有 6 字符，**很可能正是被这条挡下的**。
- `reply_unconfirmed` 的 dump 增「页面文本尾部」——这次 artifact 里只有一句「回执片段: (空)」。

### 验证到哪一步

- `py_compile` 通过；`classify_reply_blob` **离线自测 9/9**（喂字符串验判定 + 整句输出 +
  基线差分：baseline 已有「抱歉，您」时不误判）。
- **端到端没验成**：本机到 52pojie 帖子页的导航持续失败（见上），CI 那边要 lodge 重跑一次。

  —— 到那时才能定性到底是字数、间隔还是权限。
