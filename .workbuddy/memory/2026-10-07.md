# 2026-10-07

## 52pojie 回帖「回帖被拒（var STYLEID = '1', STA）」分析

CI 上`python -B -m Selenium.CheckIN.52pojie` 失败，报
`RuntimeError: 回帖被拒（var STYLEID = '1', STA）`。

### 结论：真因在服务端回执里，我们的判定代码把它剪坏了

同一份失败现场快照里，`messagetext:` 字段**已经写着真话**：

```
messagetext: 抱歉，您的请求来路不正确或表单验证串不符，无法提交
note:        服务端回执: var STYLEID = '1', STA     ← 剪坏的
```

`var STYLEID = '1', STATICURL = ...` 是 Discuz 提示页 `<head>` 里的 JS 变量，
跟报错毫无关系。

### 两个自己作的坑

**1. 句子定位串段（`_reply_snippet`）**
原写法是「marker 往前取 20 字符 + 按标签收尾取最后一段」：

```python
tail = blob[max(0, index - 20) : index + width]
tail = re.split(r"[<\n\r]", tail)[-1]
```

而采集侧 `_REPLY_BLOB_JS` 为了抓「注入 `<head>` 的回执」，把**所有 `<script>` 的文本**
都拼进了 blob。于是「往前取 20 字符」正好落到 head 里那堆变量定义上。
改成**只向右读、读到句末标点就停**，并在 marker 的所有出现位置里取截得最长的那句。

⚠️ 这是 2026-09-28「取最长命中」的**残留变种**：上次修了「选哪个短语」，
没修「定位到的是哪一段」。教训记进skill Step 4.8了。

**2. formhash 类失败没单独归类（真因）**

「请求来路不正确或表单验证串不符」是 Discuz `submitcheck()` 抛的：

```php
$_SERVER['REQUEST_METHOD'] == 'POST' && !empty($_POST['formhash'])
  && $_POST['formhash'] == FORMHASH && $_SERVER['HTTP_REFERER']
```

FORMHASH = md5(uid + TIMESTAMP + authkey + …)。含义是**这次 POST 的 formhash
与会话对不上，内容压根没发出去** —— 不是字数、不是间隔、不是权限。

关键认知：**它和「内容/权限被拒」的重试安全性完全相反**
- formhash 类：请求在入口就被打回，没入库 → 刷新重取后重试是**幂等安全**的；
- 内容类：可能已经写进去了 → 自动重试等于刷帖变灌水（仓库里已有版规警告）。

混在一起时两种策略互相打架。现在 formhash 归独立的 `formhash` kind，
并且**判定顺序上先于**泛错误短语 —— 因为「请求来路不正确」这句本身就以
「抱歉，您」开头，不先摘出来又被兜底吃掉。

三个候选根因（待下次 CI 用取证区分）：① 页面开太久（Discuz TIMESTAMP 变了）
② 注入的 Cookie 会话与页面渲染时不一致 ③ 主题没渲染 formhash 隐藏域。

### 代码改动（`Selenium/CheckIN/52pojie.py`）

- `REPLY_ERROR_MARKERS` 补 4 条formhash 关键短语；
- 新增 `REPLY_FORMHASH_MARKERS` + `_attempt` 参数，
  `PJ52_REPLY_FORMHASH_RETRIES`（默认 2）**只对 formhash 类开放自动重试**；
- `_reply_snippet` 重写（只向右读 + 取最长句）；
- 新增 `read_formhash(driver)`：提交前读页面上的 formhash（隐藏域 / JS 变量）打日志；
- 新增 `dump_reply_network(driver, tag)` + `_drain_network_log` / `_fetch_response_body`：
  从 CDP performance 日志捞真实回帖请求，落盘 POST body（看 formhash 有没有、值多少）
  与响应体；三条失败路径（formhash 用尽 / 内容被拒 / 超时未判定）都会落盘；
- 文件头补「回帖判定的坑二」段落 + `PJ52_REPLY_FORMHASH_RETRIES` 说明。

### 复用价值（已写进 skill `gha-selenium-triage` Step 4.8）

1. 报告错误片段前先扫一眼失败现场的**所有字段** —— 真话可能就在另一个字段里；
2. 「取最长命中」不等于定位对了，采集范围大时定位方向本身会串；
3. 重试安全性要按失败原因分三类（入口拒绝→可重试 / 已入库→不可重试）。

### 回帖改造（lodge 要求：两个不同帖子、软件资源区、内容「谢谢分享~」、间隔 20s）

**lodge 说的「软件资源区」= 现有的 fid=16『精品软件区』** —— 探测确认，不需要改 URL。

新增/改动：

- `REPLY_TEXT` 默认改成 `谢谢分享~`（6 字。**这条有风险**：注释里记着
  2026-09-28「帖子小于N个字符」的最小字数限制很可能就是挡的它。被拒就调长）；
- 新增 `REPLY_COUNT`（默认 2）、`REPLY_INTERVAL`（默认 20）；
- `pick_thread` → `pick_threads(driver, url, count)`：**按 tid 去重 + random.sample**。
  候选不足时**报错而不是拿同一个凑数** —— 对同一帖回两次会被 Discuz 拦（重复回复），
  更糟的是那就成了刷帖。单数版`pick_thread` 保留为兼容壳；
- 新增 `reply_many_threads()`：逐条回，**间隔等在两次提交之间**（不是跑完再补 sleep），
  单条失败**不中断后续**（第 1 条失败不代表第 2 条也失败，漏一条就是少一天互动分）；
- 主流程：部分失败时按 `REPLY_STRICT` 决定要不要整体变红；卡片文案改成
  `2/2 成功｜标题 → 结果｜标题 → 结果`。
