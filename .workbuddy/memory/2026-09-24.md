## ChromeSelenium / V2EX 登录验证码识别改造

**背景**：lodge 问 edge.v2ex.com/signin 自动化登录的验证码怎么识别。

**结论/方案**：用本地离线 OCR `ddddocr`（不依赖打码平台）。

**改动**：
- `ChromeSelenium/base.py`
  - `Ocr_Captcha()` 重写：改用**元素级截图** `element.screenshot_as_png`，替掉原来的「全屏 `save_screenshot` + `location/size` 坐标裁剪」。后者在页面滚动过、或浏览器缩放非 100% 时会错位，裁出白底导致 OCR 失败。
  - 新增 `find_captcha_element()`：多选择器依次尝试，兼容两形态——v2ex.com 老站（验证码是 `<input>` 的 `background-image`）与 edge.v2ex.com 新站（独立 `<img>`）。
  - 新增 `get_ocr()`：ddddocr 单例。原代码每次调用都 `DdddOcr()`，每次重复加载 onnx 模型（1~2s）。`show_ad` 参数旧版（<=1.4.7）不支持，已做 TypeError 降级。
  - 新增常量 `CAPTCHA_INPUT_XPATH`、`CAPTCHA_IMG_XPATHS`。
- `ChromeSelenium/Check-in/v2ex.py`：重写。加登录重试（`V2EX_MAX_ATTEMPTS`，默认 3）、`is_logged_in()` 判据、`claim_daily()` 签到。登录页 URL 可配，默认 `edge.v2ex.com/signin`。

**实测数据**（用 lodge 提供的真实截图裁剪，318x78）：
- ddddocr 在 4 种预处理（原图/2x/3x/灰度）下稳定输出 `m6iw9`，真值目测为 `mslw9` → **s→6、l→i 属形近混淆**，这是必须带重试的实证依据。
- 单元验证 6/6 通过（假元素 mock，覆盖两形态定位、小尺寸跳过、locator 失效回退、单例）。

## 追加 2：OCR 升级 —— beta 模型才是关键，不是版本号

**核心发现（实测，样本 = lodge 截图裁出的 318x78 图，真值 `msiw9`）**

| 手段 | 结果 | 结论 |
|---|---|---|
| 默认模型 | `m6iw9` ❌ | s→6 误判，**置信度高达 0.95** → 高置信度不代表对 |
| **beta 模型** | **`msiw9`** ✅ | **唯一有效手段** |
| `old=True` 模型 | `m6iw9` | 无改善 |
| `png_fix=True` | `m6iw9` | 无改善 |
| `color_filter_colors=['yellow']` | `PBnw9` | 更差 |
| 二值化(5 档)/反色/金色掩码/2x-3x 放大 | 全为其他错误结果 | 无改善，别做预处理 |
| `set_ranges(字符集)` | `m6w9` | **有害**：会丢字符 |

→ 上轮"升级版本能提识别率"的判断是错的：**1.6.1 已是最新版，照样错**。真正起作用的是切 beta 模型。

**改动**
- `base.py`
  - `get_ocr(beta=True)`：改为按模型种类双实例缓存；新增 `_build_ocr()` 逐级剔除旧版不认的 `beta`/`show_ad` 参数。
  - `Ocr_Captcha(..., beta=True)`：默认改走 beta 模型。
  - 新增 `Ocr_Captcha_Vote()`：默认模型与 beta 模型**结果一致才提交**，不一致就点击验证码图换一张重来——**换图不计入 V2EX 的登录失败次数**，比硬提交存疑结果划算。多轮不一致则用 beta 结果兜底。
  - 抽出 `_capture_captcha()` 复用取图逻辑。
- `v2ex.py`：`login_once()` 改用 `Ocr_Captcha_Vote()`。
- `requirements.txt`：`ddddocr 1.4.7 → 1.6.1`；`numpy`/`opencv-python` 由钉死改为范围 `>=1.24,<3` / `>=4.8,<5`。原因：ddddocr 1.6.x 带 `onnxruntime` 传递依赖，钉死小版本会在 CI 解析冲突。
- `check_in.yml`：新增 `Install system libs` 步骤装 `libgl1`/`libglib2.0-0`。**opencv-python 在无头 Linux 上缺 libGL 会直接 import cv2 失败**，原 workflow 因 coarcade 早挂没暴露这个问题。

**验证**：单元测试 6/6 + 7/7 通过（beta 纠正、双实例缓存、投票换图、兜底逻辑）；`pip install --dry-run --python-version 3.10` 确认 `onnxruntime 1.23.2` 有 cp310 wheel。

**踩坑澄清**：`retrying==1.3.3` 在 PyPI 上**存在**，只是没有 wheel 只有 sdist；我加 `--only-binary=:all:` 验证时误报"找不到版本"。别被这个假阳性带偏。

**方法学备注**：单样本（n=1）无法得出"识别率"结论，只能说 beta 在本例更准。真实成功率靠 beta + 投票 + 重试三层机制共同保证。
