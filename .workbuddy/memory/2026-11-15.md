# 2026-11-15

## 富途种子再次失败（#7231）—— 根因是界面语言

- 现象：11-13 起连续失败（#7226~#7229、#7231），中间 #7230 偶发成功。报错固定为
  `找不到切换按钮: ['登录']`。
- 根因：**runner 在海外时 passport 按 IP 渲染英文界面**（`<html lang="en-us">`），
  按钮文案变成 `Email` / `Phone` / `Email/User ID` / `QR code`，页面里压根没有
  名为「登录」的 `a.switch-btn`，于是 `click_switch(["登录"], ignore=False)` 直接抛错。
  间歇成功 = runner 换了 IP 段。
- 本机实测（playwright，locale=en-US）：
  - 不带 lang 参数 → 仍 `zh-cn`（说明是**按 IP** 判语言，不是浏览器 locale）
  - `?lang=zh-cn` → `zh-cn`
  - `?lang=en-us` → `en-us`（参数能覆盖默认）
  - 英文页点右上角语言菜单选「简体中文」→ 成功切回（`[data-lang="zh-cn"]` 属性跨语言稳定）

### 修复（commit adbef89，run #7232 success）

1. `website` 常量补 `?lang=zh-cn`；
2. 新增 `ensure_chinese()`：进页面先查 `document.documentElement.lang`，非 zh 就点语言菜单切回；
3. 新增 `ensure_login_mode()` / `ensure_account_tab()`：按 `page_mode()`（`.index-wrapper`
   的 `data-type`）+ 表单可见性判断，不再硬依赖「登录」这个切换链接；
4. 提交按钮文案补英文候选 `Next / Log In / Sign In`（`SUBMIT_TEXTS`）。

### 教训

富途这套页面按 IP 切换语言，凡是按中文文案定位的地方都得防这一手。farm 阶段的
「互动」「可施肥」同样中招，只是 target 参数里带了 lang=zh-cn 才一直没暴露。
