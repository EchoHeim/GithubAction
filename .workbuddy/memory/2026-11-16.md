# 2026-11-16

## V2EX 签到连挂 11 天 —— 根因 Cloudflare 托管挑战

- 现象：check_in.yml 从 **11-06 到 11-16 每天失败**（11-05 及之前基本成功，11-03/11-01 偶发失败）。
  飞书卡片固定 `签到失败 / 登录失败：已尝试 5 次 / 余额未读取到`。
- 根因：**v2ex.com 全站被 Cloudflare 托管挑战保护**。任何路径都返回「请稍候…」挑战页
  （DOM 里 `window._cf_chl_opt` + `/cdn-cgi/challenge-platform/...`，约 45KB、HTTP 200）。
  无头 Chrome 过不去 → 登录表单根本不出现 → `fill_credentials` 死等 15s 密码框超时 →
  5 轮重试撞同一堵墙 → 只报「已尝试 5 次」。原始 `error_hint` 不认识挑战页，所以连线索都没有。
- 取证方式（不需要 token）：
  `chrome.exe --headless=new --virtual-time-budget=12000 --dump-dom "<url>"`
  - `v2ex.com/`、`v2ex.com/signin`、`v2ex.com/mission/daily` → 全为挑战页
  - `edge.v2ex.com/`（430KB）、`edge.v2ex.com/signin`（27KB，标题「V2EX › 登录」）、
    `edge.v2ex.com/mission/daily`（跳登录页，说明路由存在）→ 正常
  - edge 登录页与老站同构：`<form action="/signin">`、sha256 字段名、
    `<img id="captcha-image" src="/_captcha">`、`input[type=submit]`，选择器全部命中
- 另：GitHub Actions 日志/artifact 需 token，但 `api.github.com/repos/.../actions/runs/<id>`
  与 `check-suites/<id>/check-runs` 匿名可读（只能拿状态，拿不到日志正文）。

### 修复（Selenium/CheckIN/v2ex.py）

1. 默认站点改成 `edge.v2ex.com`，SIGNIN/HOME/MISSION 三个 URL 统一从 `V2EX_BASE_URL` 派生
   （PB3_SESSION 是 host-only，不能跨域拼）。新增 `use_site()` / `site_candidates()`。
2. 新增 `challenge_hint()` 识别挑战页，并接入 `error_hint()`；`open_ready()` 遇到挑战页
   直接返回，不做 5s/15s 退避（挑战页不会因为重试而消失）。
3. 新增 `select_site()`：登录前探测候选域名（edge → v2ex.com），各给 8s 宽限看
   non-interactive 挑战能否自己跳走，不行就整组换域。
4. `login_once()` 打开登录页后先查挑战页，命中就 dump 现场并抛明确错误（不再让超时背锅）。
5. 回归测试补到 **25 个用例**（新增挑战页识别、挑战页不算登录态、整组换域、默认域名用例），全绿。
