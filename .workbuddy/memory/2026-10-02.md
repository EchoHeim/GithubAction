# 2026-10-02

## 掘金脚本：文章详情页点赞按钮线上定位不到（lodge 报障）

**现象**：签到 / 抽奖 / 沸点 / 收藏 / 关注都正常，唯独文章页两篇都报
`[WARN] 文章页未找到点赞按钮`。lodge 给了关键线索：**点赞按钮是「收藏按钮所在列的第一个」**。

**真因**：线上掘金点赞按钮的 class **不含 `like`**，`ARTICLE_LIKE_XPATHS` 整组落空；
而同列「收藏」的 class 带 `collect`，稳定命中。
更要命的是**回归测试全绿 = 夹具假过**：夹具给点赞按钮写了 `class="act-item like-btn"`，
线上根本没这个类名 —— 测试测的是夹具，不是站点。

**修法**：

- `juejin.py` 新增 `_JS_LIKE_BY_COLLECT` + `_find_like_by_collect_anchor()`：
  拿「收藏」当锚点，上爬到「同列容器」（判据：≥3 个、尺寸相近、竖向排开），
  取收藏**前面第 2 个** = 点赞（该列顺序固定：赞 / 评论 / 收藏 / 分享 / 举报）。
- `like_article` 点完**复核计数**：`-1` 说明原本已赞、被这一下点成了取消 → 立即补点还原；
  `0` 视为已赞跳过。
- 夹具照实还原：点赞按钮去掉 `like-btn`、补 48×48 竖排尺寸、点赞改成 **toggle**（照实模拟取消行为）。
- 新增断言 **T24b**（已赞再点不得取消），断言总数 32 → 33。

**环境坑（顺带根治）**：本机 `HTTP_PROXY` 开着又没 `NO_PROXY` 时，Selenium 连
**本机 chromedriver** 的请求也会被代理接管 → `WebDriverException: unhandled request`。
症状极具欺骗性：session 建得起、`browserVersion` 也读得到，但之后每一步操作全挂；
chromedriver verbose 日志里**连 `COMMAND ExecuteScript` 都没有**（请求没到 driver）。
`Selenium/base.py` 新增 `_bypass_proxy_for_localhost()`，建 driver 前自动把
`localhost / 127.0.0.1 / ::1` 追加进 `NO_PROXY`（只追加、不覆盖）；回归测试也调用它。
此前只能靠每次手工 `env -u http_proxy ...`。

**验证**：回归 33 项断言全通过，跑了两轮 —— 一轮手工清代理、一轮不清、靠脚本内自动绕行。

**改到的文件**：`Selenium/Check-in/juejin.py`、`juejin_regress_test.py`、`LOCAL_RUN.md`、`Selenium/base.py`。
